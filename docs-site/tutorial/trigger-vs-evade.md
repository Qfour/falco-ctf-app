# trigger と evade 課題の違い

この CTF の課題には、大きく 2 つのタイプがあります。ミッションに入る前に、
この違いを概念として理解しておくと、各ミッションで「自分が何を目指せば
よいのか」を早く掴めます (個々のミッションの具体的な手順はここでは
扱いません — ここではタイプの違いそのものだけを説明します)。

## trigger 課題 — 発火させることが目的

trigger 課題は、対象になっている Falco ルールを **実際に発火させる**
ことそのものが目的です。攻撃者が実際にやりそうな操作を自分の手で
再現し、それが Falco にどう見えるかを体感します。ルールが発火した
瞬間にクリア (自動判定) になり、flag の提出は不要です。

視点としては、**攻撃側の操作を実行しながら、防御側 (Falco) が
それをどう捉えるかを観察する** という体験です。

## evade 課題 — 発火させずに目的を達成することが目的

evade 課題は逆です。ある操作上の目的 (情報を読み取る・外部に
持ち出すなど) を、**対象ルールを一度も発火させずに** 達成することが
目的です。目的を達成したら、その証拠として flag を提出します。

evade 課題では「発火しない」ことは提出の前提条件であって、
それ自体がゴールではありません。目的を達成しつつ、対象ルールの
condition に当たらない経路を見つける必要があります。

## 「一度でも発火したら」の重み — evade 課題の判定

evade 課題には、trigger 課題には無い特有の仕組みがあります。
対象ルール (禁止ルール) が一度でも発火すると、その課題は
「検知済み」の状態になります。この状態は時間が経過しても自動的には
解消されません — 参加者自身が明示的にリセットする操作をするまで、
flag を提出できません。

これは、**「今この瞬間だけ隠れればよい」のではなく「最初から最後まで
一度も踏まない」ことが要求されている** という点で、trigger 課題とは
評価の性質が異なります。手を動かす前に、この非対称性を意識しておくと
進め方の見通しが立てやすくなります。

## 2 つの視点を両方体験する意味

trigger 課題では「これをやったら検知される」という攻撃側の直感を、
evade 課題では「検知される条件を外れるにはどう動けばよいか」という
防御回避の視点を養います。同じ操作対象 (ファイル・プロセス・
ネットワーク) を、検知される側と検知を外す側の両方から見ることで、
Falco が実際に何を判定基準にしているかの理解が深まります。

これで座学チュートリアルの内容は一通りです。実際の condition の
読み方や観測ポイントの一覧は、この Tutorial タブの他の章や
コマンド集を随時見返しながら、ミッションに進んでください。
