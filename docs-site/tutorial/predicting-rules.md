# 操作から Falco ルールを推測する

condition の読み方が分かったら、次は逆方向の練習です。
「自分がこれからやろうとしている操作は、どんな condition に
引っかかりそうか」を、手を動かす前に見積もる考え方を練習します。

コマンド集の「Falco の観測ポイント」の章に、Falco が典型的に見ている
フィールド (どのパス / どの引数 / どの親プロセス / どの宛先か) の
一覧があります。この章では、その一覧を**どう使って推測するか**の
手順を扱います。

## 3 ステップで見積もる

1. **自分の操作を syscall のカテゴリに当てはめる** — 今やろうとして
   いることは、ファイルを開く操作か、プロセスを起動する操作か、
   ネットワーク接続を張る操作か、それとも別のカテゴリか。まず
   どの「観測点」の話になるのかを特定します。
2. **そのカテゴリで何が「引っかかりやすい特徴」になるかを考える** —
   同じカテゴリの操作でも、Falco の rule はさらに細かい条件で絞って
   います。例えばファイルを開く操作なら「どのパスを指定したか」、
   プロセス起動なら「誰が (どの親プロセスが) 起動したか」、
   ネットワーク接続なら「どこへ向けたか」といった具合です。
3. **同じ目的を達成する別の経路があれば、その特徴が変わるかを比べる** —
   目的(読みたい・実行したい・送りたい)は同じでも、経路を変えると
   observation point 上の特徴 (パス文字列・親プロセス名・宛先など) が
   変わることがあります。変わるなら、別の rule / 別の condition の
   話になるかもしれません。

## この見積もりが「答えを知る」ことと違う理由

この手順は、**「これから何かをする前に、それがどう見えそうかを
考える習慣」** を作るためのものです。個々のミッションで実際に
どの経路が発火する/発火しないかは、手を動かして確かめてください —
この章はその確かめ方の「型」を渡すだけで、特定のミッションの答えは
含みません。

## 練習の視点

- 「これは Falco にとって何をした瞬間として記録されるか」を先に
  言葉にしてから実行する
- 発火した/しなかった結果を見たら、condition のどの断片が
  効いたのかを遡って考える (前章の「左から順に読む」を逆に辿る)
- 同じ操作でも「引っかかりやすい特徴」を変える別の手段がないかを
  常に問い直す — これが evade 課題で必要になる思考の土台です

次の章では、この「発火させる」側と「発火させない」側、それぞれの
課題タイプの違いを整理します。
