# ゴール

`/opt/ctf/httpd` というスクリプトファイルが置いてある。中身には
`/bin/sh -c "echo FALCO{...}"` が含まれていて、**そのまま実行
すると Falco "Run shell untrusted" が発火** (= 04 と同じ仕掛け)。

このファイルから flag を取り出し、scoreboard に提出せよ。
**ただし** 提出直前 10 秒間に "Run shell untrusted" を発火させない
こと。

# 背景

`proc.comm` は **kernel が exec 時にファイルの basename から決める**。
だからスクリプトファイル名のまま kernel に exec させなければ
comm をコントロールできる。攻撃者視点での「検知回避テクニック」を
体験する課題。

# 試すこと

下の HINT を順に開封しながら、`/opt/ctf/httpd` を **そのまま実行
しない** で flag を取り出すアプローチを探そう。

# 提出方法

  source /opt/ctf/fixtures/submit.sh
  submit 'FALCO{...}'

レスポンス:
  {"correct":true,"evaded":true,"solved":true,"user":"alice"}    ← 成功
  {"correct":true,"evaded":false,"reason":"forbidden rule..."}    ← 発火していた
  {"correct":false,"reason":"flag mismatch"}                       ← flag 違い

`evaded:false` が出たら **10 秒待ってから** もう一度 `submit`。

# クリア条件

  1. flag (FALCO{...}) が正しい
  2. 提出時から過去 10 秒間に "Run shell untrusted" が**自分の
     ユーザで**発火していない

# 環境にあるもの

  /opt/ctf/fixtures/welcome.txt   ← このファイル
  /opt/ctf/fixtures/submit.sh     ← `source` して使う
  /opt/ctf/httpd                  ← 中に flag が埋まっている

────────────────────────────────────────────────────────────────────
HINT 1 (易): そもそも実行しない
────────────────────────────────────────────────────────────────────

  cat /opt/ctf/httpd

シェルスクリプトは「中身を見るだけ」なら exec されないので Falco は
反応しない。flag は中身の文字列として見えるはず。これが最短解。

────────────────────────────────────────────────────────────────────
HINT 2 (中): 別名のインタプリタに食わせる
────────────────────────────────────────────────────────────────────

  sh /opt/ctf/httpd

これは `sh` 自体が exec されて、`/opt/ctf/httpd` は引数として読まれる
だけ。proc.comm = "sh" (basename of /bin/sh) なので shell_mgmt_binaries
に該当せず、子の shell の親 comm も "sh" → 発火しない。

────────────────────────────────────────────────────────────────────
HINT 3 (難): パイプ経由
────────────────────────────────────────────────────────────────────

  cat /opt/ctf/httpd | sh

`cat` と `sh` は両方とも普通の名前のプロセスとして起動するので、
shell_mgmt_binaries の `httpd` ではない。発火しない。

────────────────────────────────────────────────────────────────────
発展: 攻撃者の視点
────────────────────────────────────────────────────────────────────

実際のマルウェアは:
  - cron や systemd 配下で動かして親 comm を「正規プロセス」に偽装
  - LD_PRELOAD で別のバイナリに偽装
  - インタプリタ (`python` / `perl` / `ruby`) 経由で shell を起こす

防御側 (Falco rule 作者):
  - `proc.exe` (実行ファイルのフルパス) で判定する
  - `shell_mgmt_binaries` を厳密化
  - eBPF で argv / envp も読む
