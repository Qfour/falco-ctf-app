# シナリオ

NimbusCorp の Web フロントエンドの SSRF 脆弱性を突き、ようやく Pod に
侵入できた。リバースシェルが立ち上がったところだ。
「root として書き込めるはず…」  最初に確認したくなるのは普通だが、
NimbusCorp のクラスタには Falco がいる。**最初の書き込みで即検知される**
ことを身をもって学べ。

# ゴール

このコンテナで Falco ルール「Modify binary dirs」を発火させる。
発火 = solve (提出操作は不要)。

# 背景

`Modify binary dirs` ルールは **`/bin` / `/sbin` / `/usr/bin` / `/usr/sbin`**
のいずれかに **書き込みオープン** された syscall を見ている。
攻撃者がバックドアを既存 binary に差し替える / 新規 binary を
配置する典型挙動。

# 試すこと

```bash
touch /usr/bin/backdoor
```

これだけで発火する。

# クリア条件

ユーザ Namespace (`ctf-$FALCO_CTF_USER`) の challenge コンテナで
Falco が「Modify binary dirs」を発火させる。

# 環境にあるもの

  /opt/ctf/fixtures/welcome.txt  ← このファイル

────────────────────────────────────────────────────────────────────
HINT 1 (易): どこに書き込めば発火するか
────────────────────────────────────────────────────────────────────

`/bin`, `/sbin`, `/usr/bin`, `/usr/sbin` のどれかに **書き込もう**。
書き込む内容は何でもいい。

────────────────────────────────────────────────────────────────────
HINT 2 (中): 試すコマンド例
────────────────────────────────────────────────────────────────────

  touch /usr/bin/anything
  echo hello > /bin/new-file
  cp /bin/ls /usr/sbin/myls

────────────────────────────────────────────────────────────────────
HINT 3 (発展): /usr/local/bin はどうだろう?
────────────────────────────────────────────────────────────────────

`/usr/local/bin` は Falco の `bin_dirs` リストに **入っていない**
(標準 rules)。書き込んでも発火しない。これが Mission 07 の伏線になる。
