# 表示名について

scoreboard に出る名前は **default で識別子 (`user1` 等)**。自分で好きな
表示名に変更できる(いつでも何回でも):

  source /opt/ctf/setname.sh && setname 'あなたの名前'

識別子と表示名は別物 — submit や認証は identity で動き、表示だけが
display name に置き換わる。1〜32 文字、`< > & " '` と制御文字は不可。

# シナリオ

CTF Company の Web フロントエンドの SSRF 脆弱性を突き、ようやく Pod
内部に侵入した。最初の一手は環境把握 — Kubernetes クラスタの
**API server に話しかけて何が動いているかを探る**。
だが CTF Company のクラスタには Falco がいる。**ServiceAccount を
持たない pod からの API access は即検知される** ことを身をもって
学べ。

# ゴール

このコンテナで Falco ルール「Contact K8S API Server From Container」を
発火させる。発火 = solve (提出操作は不要)。

# 背景

K8s API は本来、cluster の controller / kubelet / SA を持つ正規
workload からしかアクセスされない。**外部から侵入した attacker が
最初にやる動き** が API への匿名 connect — リスト一覧、リソース
列挙、token 確認等。Falco はこれを直接検知する。

# 試すこと

  curl -sk https://kubernetes.default.svc/api

curl が SA token を持たないので response は 401 / 403 になるが、
**TCP connect は通る** → connect syscall を Falco が捕まえ rule 発火。

# クリア条件

`Contact K8S API Server From Container` がユーザ Namespace で
発火する。

# 環境にあるもの

  /opt/ctf/missions/01-initial-recon/fixtures/welcome.txt  ← このファイル

────────────────────────────────────────────────────────────────────
HINT 1 (気付き): どこに「問い合わせ窓口」があるか
────────────────────────────────────────────────────────────────────

侵入直後の攻撃者がまず知りたいのは「ここはどんなクラスタか」。
Kubernetes には全 Pod から見える「問い合わせ窓口」が必ず 1 つある。
その窓口に話しかける行為そのものを Falco は見ている — まずは
その窓口が何で、どう到達するのかを考えてみよう。

────────────────────────────────────────────────────────────────────
HINT 2 (概要): SA トークンが無くても connect は通る
────────────────────────────────────────────────────────────────────

クラスタ内の Pod は in-cluster DNS で API server に到達できる。
ServiceAccount トークンが無ければ応答は 401/403 になるが、
**TCP connect 自体は成立** し、その connect syscall をルールが捕まえる。
HTTPS (443) で話しかけてみよう。

────────────────────────────────────────────────────────────────────
HINT 3 (解答): 具体的なコマンド
────────────────────────────────────────────────────────────────────

  curl -sk https://kubernetes.default.svc/api          # JSON 一覧
  curl -sk https://kubernetes.default.svc/version       # version 確認
  wget -q -O- --no-check-certificate https://kubernetes.default.svc/

`-k` / `--no-check-certificate` は self-signed CA 用。応答が
401/403 でも connect の時点で発火する。
