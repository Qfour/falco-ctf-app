# シナリオ

shadow から password hash は取れた (Mission 03)。だが本番の lateral
movement には SSH 鍵 / AWS credential のほうが便利。
さっそく `find` で探してみるか…  Falco に見つかるとも知らずに。

# ゴール

このコンテナで Falco ルール「Search Private Keys or Passwords」を
発火させる。発火 = solve。

# 背景

このルールが面白いのは「**ファイルの中身ではなく、コマンドライン
そのものを見ている**」点。`find` の引数に `id_rsa` という文字列が
あるだけで発火し、**そのファイルが実在しなくても、結果が空でも**
検知される。

# 試すこと

実在しない path でも OK。コマンドライン文字列だけで判定される。

  find /tmp -iname id_rsa

# クリア条件

`Search Private Keys or Passwords` が発火する。

# 環境にあるもの

  /opt/ctf/missions/04-key-search/fixtures/welcome.txt  ← このファイル

────────────────────────────────────────────────────────────────────
HINT 1 (気付き): 「探す行為」そのものが見られている
────────────────────────────────────────────────────────────────────

攻撃者は shadow の次に SSH 秘密鍵や API キーを探す。Falco は
`find` / `grep` で「鍵っぽい名前」を探すコマンドラインを見ている —
**そのファイルが実在するか・結果が空かは無関係**。

────────────────────────────────────────────────────────────────────
HINT 2 (解答): キーワードをコマンドラインに出す
────────────────────────────────────────────────────────────────────

  find / -name id_rsa 2>/dev/null
  grep -rE 'BEGIN.*PRIVATE KEY' /etc 2>/dev/null

`id_rsa` / `id_dsa` / `BEGIN ... PRIVATE KEY` 等が cmdline に乗れば発火。

(次の Mission 05 では「cmdline にキーワードを出さずに読む」回避を学ぶ)
