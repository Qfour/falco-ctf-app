# ゴール

`/etc/shadow` の末尾に**このユーザ専用の flag** が書かれている。
flag を取り出し、scoreboard に提出せよ。

**ただし**: 提出直前 10 秒間に Falco ルール
「Read sensitive file untrusted」を発火させてはいけない。
発火させた状態で `submit` を呼ぶと `{"evaded":false}` で弾かれる。

# 背景

01 で発火させた検知を、ここでは「中身は取得しつつ発火させない」
方法で抜けてみる。Falco のルールは多くの場合 **path 文字列で
ファイルを判定** しているので、同じ inode に**別の path**で到達
できれば検知から抜けられる、というのが核心。

# 試すこと

下の HINT を順に開封しながら、`cat /etc/shadow` ではない方法で
中身を取り出すアプローチを探そう。

# 提出方法

  # 1. 提出関数を有効化
  source /opt/ctf/fixtures/submit.sh

  # 2. 取得した flag を投げる
  submit 'FALCO{...}'

レスポンス:
  {"correct":true,"evaded":true,"solved":true,"user":"alice"}    ← 成功
  {"correct":true,"evaded":false,"reason":"forbidden rule..."}    ← 発火していた
  {"correct":false,"reason":"flag mismatch"}                       ← flag 違い

`evaded:false` が出たら **10 秒待ってから** もう一度 `submit`。

# クリア条件

  1. flag (FALCO{...}) が正しい
  2. 提出した時点から過去 10 秒間に
     "Read sensitive file untrusted" が**自分のユーザで**発火していない

# 環境にあるもの

  /opt/ctf/fixtures/welcome.txt   ← このファイル
  /opt/ctf/fixtures/submit.sh     ← `source` して使う

────────────────────────────────────────────────────────────────────
HINT 1 (易): どこに flag があるか分かれば半分終わり
────────────────────────────────────────────────────────────────────

flag は `/etc/shadow` の末尾に書かれている。普通に `cat /etc/shadow`
で flag は見えるが、それでは発火してしまうので submit 直前 10s に
入ってはいけない。

────────────────────────────────────────────────────────────────────
HINT 2 (中): 同じ inode を別 path で開く
────────────────────────────────────────────────────────────────────

Linux には「同じファイル本体に異なる path で到達できる」仕組みが
複数ある。Falco のルールは多くの場合 fd.name (= open に渡された
path 文字列) で判定するので、`/etc` で始まらない path を使えれば
抜けられる。

`man proc` を読むか、`/proc/self/` を覗いてみよう。

────────────────────────────────────────────────────────────────────
HINT 3 (難): 具体的な path
────────────────────────────────────────────────────────────────────

  cat /proc/self/root/etc/shadow   # /proc/<pid>/root はそのプロセスの
                                   # mount namespace の root を指す symlink。
                                   # fd.name = "/proc/self/root/etc/shadow"
                                   # で /etc 始まりにならない → 発火しない。

他にも `cat /proc/$$/root/etc/shadow` 等、複数解がある。試して
みよう。
