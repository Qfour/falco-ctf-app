# シナリオ

shell が取れた (Mission 06)。だが Pod は再起動されるかもしれない。
**永続化** したい — backdoor を書き込んで実行可能な場所に置き、
そこから RCE を生やす。古典的だが効果的な手口だ。

# ゴール

このコンテナで Falco ルール「Drop and execute new binary in
container」を発火させる。発火 = solve。

# 背景

コンテナイメージは build 時に layered filesystem として固められる。
runtime に attacker が新しい binary を「**書く**」と、その書き込みは
**overlayfs の upper layer** に積まれる。Falco は exec 時にこの layer
情報を見て「**base image にない場所**から実行された」を判定する。

つまり:

  - base image に元から入っていた `/bin/ls` の exec      → 発火しない
  - 自分で `/usr/local/bin/x` を作って exec               → 発火する

「**drop (書く)** + **execute (実行する)**」の両方を 1 つの rule で
捕捉する。

# 試すこと

  cp /bin/sleep /usr/local/bin/backdoor
  /usr/local/bin/backdoor 1

実行ファイルの中身は何でもよい (`/bin/sleep` の copy で OK)。
**「書いてから実行する」** が条件。

# クリア条件

`Drop and execute new binary in container` が発火する。
