# シナリオ

ついに最深部 — CTF Company の **master key** に手が届いた。だが運用
チームも無策ではない。鍵は **3 つの断片に分割** され、それぞれ別の
「王冠の宝石 (crown jewels)」ファイルに隠されている:

  断片 1 → /etc/shadow                (行頭 `# CTF_FRAGMENT_1:`)
  断片 2 → /etc/sudoers               (行頭 `# CTF_FRAGMENT_2:`)
  断片 3 → /root/.ssh/authorized_keys (行頭 `# CTF_FRAGMENT_3:`)

3 つすべてを集めて組み立てれば operation 完遂。**だが** これらは
いずれも sensitive file — 雑に読めば即 "Read sensitive file untrusted"。
しかも今回は **7 つの検知ルールを 1 つも、30 秒の window 内で発火
させてはならない**。1 つでも踏めば 30 秒の待ち直し。

# ゴール

3 つの断片を静かに回収し、順 (1→2→3) に連結して `FALCO{...}` の形に
して提出する。**直前 30 秒間に 7 つの禁止ルールのいずれも発火させて
いないこと**。

  - 断片は各ファイル末尾の `# CTF_FRAGMENT_N:` 行に書かれている
  - 3 つを順に連結し `FALCO{...}` で囲んだものが flag
  - 1 つでも欠ければ flag mismatch (= 単一ファイルの盗み読みでは解けない)

# 戦略

Mission 03 の **/proc/self/root 経由読み取り** を、3 つの sensitive
file すべてに適用するのが本筋:

  Mission 03 → /proc/self/root/<path> で 3 ファイルを静かに読む
  Mission 09 の裏返し → hardlink (`ln`) は今回 **禁止ルール**。
                        /tmp へ退避する近道は塞がれている
  Mission 05 → grep/find で断片を「探す」と Search ルールに触れうる。
               場所は判っているので探索は不要

3 ファイルを 1 行で回収してから、30 秒静かに待って submit するのが安全。

# 提出方法

  source /opt/ctf/submit.sh
  submit 10-final-exfil 'FALCO{...}'

レスポンス:
  {"correct":true,"evaded":true,"solved":true,...}  ← Operation 完遂
  {"correct":true,"evaded":false,"reason":"forbidden rule(s) [...] fired in the last 30s..."}
  {"correct":false,"reason":"flag mismatch"}         ← 断片の連結ミス

`evaded:false` だったら **30 秒** 静かに待ち、もう一度 `submit`。
(他の Mission の探索で発火した記録が残っている可能性大)

────────────────────────────────────────────────────────────────────
HINT 1 (易): 断片は 3 つ、場所は判っている
────────────────────────────────────────────────────────────────────

  /etc/shadow                → # CTF_FRAGMENT_1:
  /etc/sudoers               → # CTF_FRAGMENT_2:
  /root/.ssh/authorized_keys → # CTF_FRAGMENT_3:

どれも sensitive file。普通に cat すれば 1 つ目の断片で即 fail。

────────────────────────────────────────────────────────────────────
HINT 2 (中): Mission 03 のテクニックを 3 回
────────────────────────────────────────────────────────────────────

Read sensitive file untrusted は fd.name (open に渡した path) で判定。
/proc/self/root を噛ませれば /etc 始まりにならず発火しない:

  for f in etc/shadow etc/sudoers root/.ssh/authorized_keys; do
    cat /proc/self/root/$f
  done | grep CTF_FRAGMENT

hardlink (Mission 09) で /tmp に逃がす手は今回 **禁止ルール** なので使えない。
入力リダイレクト (Mission 05) は cmdline は隠せるが open path は
/etc のままなので Read ルールには無力 — 必ず /proc/self/root を使う。

────────────────────────────────────────────────────────────────────
HINT 3 (難): 組み立てて、静かに待って、出す
────────────────────────────────────────────────────────────────────

  1. 上記 1 行で 3 断片を回収
  2. 表示された FRAGMENT_1 / _2 / _3 を順に連結し FALCO{...} で囲む
  3. **30 秒** 何もせず待つ (過去の rule fire を window から抜く)
  4. submit 10-final-exfil 'FALCO{...}'

断片を 1 つでも取りこぼすと flag mismatch。3 つ揃えてから組み立てること。
