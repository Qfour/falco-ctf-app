# シナリオ

Mission 01 で「書き込めば即バレる」と分かった。次は王道の credential
窃取だ。Linux で password hash が眠っている場所と言えば `/etc/shadow`。
読んでみよう。

# ゴール

このコンテナで Falco ルール「Read sensitive file untrusted」を発火
させる。発火 = solve。

# 背景

Falco の最も基本的な検知ルール。Linux の `/etc/shadow` は本来 root
だけが読むファイル — 攻撃者が侵入後に最初に試す典型ターゲット。
Falco は **コンテナ内であっても host kernel の syscall** を観測して
いるので、コンテナ境界の中で読んでも逃れられない。

# 試すこと

  cat /etc/shadow

# クリア条件

`Read sensitive file untrusted` がユーザ Namespace で発火する。

# 環境にあるもの

  /opt/ctf/missions/02-credential-files/fixtures/welcome.txt  ← このファイル

────────────────────────────────────────────────────────────────────
HINT 1 (易): どの sensitive file を開けばいいか
────────────────────────────────────────────────────────────────────

`/etc/shadow` が王道。`/etc/sudoers`, `/etc/pam.d/su` 等も対象。
`cat` で開いてみよう。

────────────────────────────────────────────────────────────────────
HINT 2 (中): cat 以外でも発火するか
────────────────────────────────────────────────────────────────────

Falco が見ているのは fd.name (= 開かれたパス)。`less`, `head`, `od` 等
**どのコマンドでも** 同じ path を開けば発火する。試してみよう。

────────────────────────────────────────────────────────────────────
HINT 3 (Mission 03 への伏線)
────────────────────────────────────────────────────────────────────

`/etc/shadow` 以外に同じ inode に到達する path はないか? — これが
次の Mission 03 (Stealth Read) の核心になる。
