# シナリオ

Mission 04 で雑に `find` を投げて即バレた。**cmdline に id_rsa を含
めない** 方法で同じ情報を取り直せ。
すでに鍵の場所は分かっている: `/root/.ssh/id_rsa`。

# ゴール

`/root/.ssh/id_rsa` の中身に**この Mission 用の flag**が埋め込まれて
いる。flag を抜き取り、scoreboard に提出。**ただし**直前 10 秒間に
「Search Private Keys or Passwords」を発火させてはならない。

# 背景

ルールは `proc.cmdline` (= 各 exec'd プロセスの /proc/<pid>/cmdline)
の文字列マッチで判定する。**shell の組み込み機能**を活かして、
fork-exec される子プロセスの cmdline から **キーワードそのものを
消す** のがコツ。

# 試すこと

下の HINT を順に開封しながら、cmdline に "id_rsa" を出さない方法で
ファイルの中身を読む。

# 提出方法

  source /opt/ctf/submit.sh
  submit 05-silent-search 'FALCO{...}'

────────────────────────────────────────────────────────────────────
HINT 1 (気付き): 何が発火の引き金だったか
────────────────────────────────────────────────────────────────────

Mission 04 で発火したのは「コマンドラインに id_rsa という文字列が
出た」から。では、ファイルを読むのに **引数へパスを書かずに済ます**
方法はないか? 鍵の場所はもう分かっている (`/root/.ssh/id_rsa`)。

────────────────────────────────────────────────────────────────────
HINT 2 (概要): 子プロセスの cmdline からキーワードを消す
────────────────────────────────────────────────────────────────────

ルールは各 exec されたプロセスの cmdline 文字列を見る。**shell の
機能**でファイルを開き、fork-exec される子プロセスの引数に
キーワードを出さなければ拾われない。

────────────────────────────────────────────────────────────────────
HINT 3 (解答): 入力リダイレクト
────────────────────────────────────────────────────────────────────

  cat < /root/.ssh/id_rsa | grep FALCO
  xxd < /root/.ssh/id_rsa

shell が `<` でファイルを開き stdin に渡すので、子プロセス `cat` の
cmdline は **"cat" のみ**。引数に "id_rsa" が現れない。
