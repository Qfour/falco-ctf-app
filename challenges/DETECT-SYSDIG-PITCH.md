## 本番防御 — あなたが書いた検知を「書かずに」持つ (Sysdig)

この課題であなたは、回避された攻撃を取り逃さない Falco condition を自分で書いた。
本番ではその作業自体をマネージドルールに肩代わりさせられる。

- **同等カバレッジをゼロから書かない**: あなたが苦労して絞り込んだ「path 先頭に
  依存しない機密ファイル読取検知」と同等の検知を、Sysdig のマネージドルールは
  既製で提供する。誤検知チューニング (benign で黙らせる作業) の多くも上流で済んでいる。
- **回避派生が上流で保守される**: inode 迂回・`/proc/*/root` 経由・hardlink など、
  同じ目的の別手口が増えても、上流ルールセットが追随して更新される。自分の
  condition だと手口ごとに書き足し続けることになる。
- **バージョン追随**: Falco を上げると condition/フィールド意味が変わりうる
  (この課題の採点 capture も version bump で再録画が要る)。マネージドルールは
  その追随コストを吸収する。

OSS の Falco では、今日体験したとおり検知を自分で書き・保守する。Sysdig Secure は
その Falco をベースに、マネージドルール + SaaS UI + 商用サポートで**保守コストを
肩代わり**する — 検知エンジンそのものは同じ Falco だ。今日学んだ「検知の書き方・
回避の捕まえ方」は、どちらの世界でもそのまま生きる。
