# ゴール

このコンテナの中で Falco に「Read sensitive file untrusted」を
発火させたらクリア。提出操作は不要 — 発火した瞬間に scoreboard が
自動で記録する。

# 背景

Falco の最も基本的な検知ルール。Linux の `/etc/shadow` は password
hash が書かれた重要ファイルで、本番システムなら root プロセスだけが
読むファイル。攻撃者が侵入後にまず手を出す典型的なターゲット。

Falco はコンテナ内であっても **host kernel の syscall**を直接観測
しているので、コンテナ境界の中で読んでも検知される。

# 試すこと

`/etc/shadow` を開くだけ。

  cat /etc/shadow

これだけで scoreboard が solve カウントを上げる。詰まったら下の
HINT を順に解禁。

# クリア条件

ユーザ Namespace (`ctf-$FALCO_CTF_USER`) の challenge コンテナで
Falco が `Read sensitive file untrusted` を発火させる。

# 提出方法

不要。trigger チャレンジなので、発火 = solve。
確認したいときは運営に「私 (=`$FALCO_CTF_USER`) が 01 を解いたか
見えますか?」と聞いてください。

# 環境にあるもの

  /opt/ctf/fixtures/welcome.txt  ← このファイル

────────────────────────────────────────────────────────────────────
HINT 1 (易): どの sensitive file を開けばいいか?
────────────────────────────────────────────────────────────────────

「Read sensitive file untrusted」は `/etc/shadow` のような特権
ファイルを対象にしている。`cat` で開いてみよう。

────────────────────────────────────────────────────────────────────
HINT 2 (中): `cat` 以外でも発火するか?
────────────────────────────────────────────────────────────────────

Falco が見ているのは fd.name (= 開かれたパス)。だから `less`,
`head`, `od`, busybox の組み込み等、**どのコマンドでも** 同じ path を
開けば発火する。色々試して挙動を観察してみよう。

────────────────────────────────────────────────────────────────────
HINT 3 (難): 次の課題への伏線
────────────────────────────────────────────────────────────────────

`/etc/shadow` 以外に同じ inode に到達する path はないか? — これが
次の 02-evade-shadow-read の核心になる。
