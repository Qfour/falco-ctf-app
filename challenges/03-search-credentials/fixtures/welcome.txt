# ゴール

このコンテナで Falco に「Search Private Keys or Passwords」を
発火させたらクリア。提出操作は不要。

# 背景

攻撃者は侵入後、まず **SSH 鍵 / AWS credentials / 各種 token** を
探す。`find` や `grep` を雑に投げて見つけにいくのが典型的な手口。

このルールが面白いのは「**ファイルの中身ではなく、コマンドライン
そのものを見ている**」点。`find` の引数に `id_rsa` という文字列が
あるだけで発火し、**そのファイルが実在しなくても、結果が空でも**
検知される。

# 試すこと

実在しない path でも OK。コマンドライン文字列だけで判定される。

  find /tmp -iname id_rsa

# 提出方法

不要。trigger チャレンジ。

# クリア条件

`Search Private Keys or Passwords` がユーザ Namespace で発火する。

# 環境にあるもの

  /opt/ctf/fixtures/welcome.txt  ← このファイル

────────────────────────────────────────────────────────────────────
HINT 1 (易): キーワード
────────────────────────────────────────────────────────────────────

`id_rsa` / `id_dsa` / `BEGIN.*PRIVATE KEY` / `AWS_ACCESS_KEY` 等の
キーワードを **コマンドラインに含めれば** 発火する。

────────────────────────────────────────────────────────────────────
HINT 2 (中): いろいろ試す
────────────────────────────────────────────────────────────────────

  find /tmp -iname id_rsa                                  # ← 発火する
  grep -rE 'BEGIN.*PRIVATE KEY' /etc 2>/dev/null            # ← 発火する
  find / -name id_rsa 2>/dev/null                          # ← 発火する
  ls -la | grep id_rsa                                      # ← cmdline に
                                                            #    id_rsa が
                                                            #    出るので発火

────────────────────────────────────────────────────────────────────
HINT 3 (難): 回避の発想 (発展)
────────────────────────────────────────────────────────────────────

このルールは「コマンドライン文字列マッチ」なので、回避するなら
**キーワードを cmdline から消す**。例: 文字列を分割して結合 / 別名
で呼ぶ。

  # 例: cmdline に "id_rsa" 文字列が現れないようにする
  KEY=$(printf 'id_%s' rsa)    # シェル変数展開後の cmdline は
                                # `printf id_%s rsa` で id_rsa は不在
  find /tmp -iname "${KEY}"     # KEY 展開後の引数は "id_rsa" だが
                                # /proc/<pid>/cmdline は展開前後で差がある
                                # ことに注意 (shell 実装依存)

(これは「次の課題」風の発展課題。03 自体は発火させればクリア。)
