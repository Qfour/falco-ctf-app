# ゴール

このコンテナで Falco に「Run shell untrusted」を発火させたら
クリア。提出操作は不要。

# 背景

「Web サーバの脆弱性で RCE を取られて shell が起きた」という典型的
攻撃シナリオを Falco がどう検知するか。

Falco が見るのは **shell プロセスの親の comm (proc.pname)**:

- 親が `bash` / `sh` / `zsh` 等 → 普通のオペレータ操作。発火しない
- 親が `httpd` / `nginx` / `apache2` / `postgres` 等 → 異常。発火

Linux カーネルは `/proc/<pid>/comm` を **実行ファイルの basename**
から決めるので、自分でファイル名を選んで実行ファイルを置けば
proc.pname を制御できる。これは「攻撃者がやる事」をシミュレートする。

# 試すこと

fixtures に用意されたラッパーをそのまま実行:

  sh /opt/ctf/fixtures/fake-httpd.sh

これは内部で:
  1. `/tmp/httpd` という shell スクリプトを書き出し (comm = "httpd")
  2. それを exec
  3. `/tmp/httpd` の中で `/bin/sh -c "..."` が走る
  4. Falco: proc.pname = "httpd" → shell の起動 → 発火

# 提出方法

不要。trigger チャレンジ。

# クリア条件

`Run shell untrusted` が発火する。

# 環境にあるもの

  /opt/ctf/fixtures/welcome.txt       ← このファイル
  /opt/ctf/fixtures/fake-httpd.sh     ← サンプル攻撃シナリオ

────────────────────────────────────────────────────────────────────
HINT 1 (易): 一発実行
────────────────────────────────────────────────────────────────────

  sh /opt/ctf/fixtures/fake-httpd.sh

これで発火する。

────────────────────────────────────────────────────────────────────
HINT 2 (中): 自分で組む
────────────────────────────────────────────────────────────────────

  cat > /tmp/httpd <<'EOF'
  #!/bin/sh
  /bin/sh -c "ls > /dev/null"
  EOF
  chmod +x /tmp/httpd
  /tmp/httpd

実行ファイル名が `httpd` (basename) なので、その子プロセス (shell) の
proc.pname は "httpd" になる → ルール発火。

────────────────────────────────────────────────────────────────────
HINT 3 (難): 試しに別名で動かしてみる
────────────────────────────────────────────────────────────────────

  cp /tmp/httpd /tmp/myscript
  /tmp/myscript

これは発火しない。proc.pname = "myscript" は `shell_mgmt_binaries`
に含まれないから。→ これが 05-evade-shell-spawn の核心になる。
