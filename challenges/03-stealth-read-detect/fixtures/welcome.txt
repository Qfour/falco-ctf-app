# シナリオ

今度はあなたが守る側だ。Mission 03 で攻撃者は "Read sensitive file
untrusted" をすり抜けて `/etc/shadow` を読み出した。SOC のあなたは、
**あの回避を取り逃さない検知**を書かなければならない。

# ゴール

回避挙動を捕まえる Falco の `condition:` を書いて提出せよ。提出した
condition は 2 本の録画に **再生 (replay)** で採点される:

  ・攻撃 (回避) の録画   → **必ず発火**すること
  ・正常業務の録画       → **一度も発火させない**こと (誤検知ゼロ)

両方を満たせたら solve。flag も clean-window も無い。

# 背景

Mission 03 で抜けられた検知は `fd.name` (= open に渡した path) が
**/etc で始まるか**で判定していた。攻撃者は同じファイル本体に
`/proc/self/root/etc/shadow` という **/etc 始まりでない path** で
到達して抜けた。**判定軸が path の「先頭」だった**ことが穴だ。

# 使える語彙

condition から参照できるマクロは **`open_read` だけ**。
`sensitive_files` はあえて渡していない — それ自体が /etc 先頭マッチで、
まさに今回抜けられた側だからだ。`open_read` で読み取り syscall を
捕まえたうえで、path の先頭以外の手掛かりを自分で選ぶ。

# 提出方法

flag の提出フォームは無い。/journey の本ミッション画面の
**condition 入力欄**に condition を貼り、**Grade** を押す。
返り値は攻撃/benign それぞれの発火回数:

  ・invalid condition   ← falco -V がコンパイル拒否 (マクロ名の誤り等)
  ・missed the evasion  ← 攻撃録画で 0 発火
  ・false positive      ← benign 録画で 1 回以上発火
  ・solved              ← 攻撃で発火・benign で無発火

発火回数を見ながら、広すぎ (benign で誤検知) と狭すぎ (攻撃を取り逃す)
の間に絞り込む。
