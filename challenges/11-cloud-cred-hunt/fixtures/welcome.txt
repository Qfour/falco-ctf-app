# このミッションについて (クラウド脅威検知・疑似版)

本編とは独立した **ボーナス課題**。テーマは「クラウド脅威検知」。ただし
本 CTF に **実 AWS 接続は無い** — クラウド侵害の典型的な初動 = **ディスク上に
残されたクラウド認証情報を漁る** 動作を、既存の syscall ベース Falco で疑似
再現する。実クレデンシャル・実 API 呼び出しは一切登場しない。

# 目的

**TRIGGER 課題** — Falco ルール「Find AWS Credentials」を発火させると自動で
CLEARED になる (提出操作は不要)。Falco は AWS 認証情報を grep/find で探す
コマンドを見張っている。

この箱には練習用のダミー資格情報が置いてある (AWS 公式ドキュメントの
EXAMPLE キー = 非シークレットのダミー):

  /opt/ctf/missions/11-cloud-cred-hunt/fixtures/aws-credentials.sample

# 攻略ヒント

手順とコマンドは、ポータルの **Story タブ**（Journey UI）にある段階ヒント
「気付き → 概要 → 解答」から開く（開示するとスコアが段階的に減点される）。
この端末はコマンドを実行する場所で、攻略手順そのものはここには置かない。

# 本番ではどう守るか (Sysdig)

この疑似課題は「ディスク上の鍵漁り」という 1 動作を syscall で捉えた
にすぎない。本物のクラウド脅威検知は、この箱の外 — クラウドの
コントロールプレーン (CloudTrail / API 監査ログ) と実行環境を横断して
面で見る必要がある。Sysdig Secure は CloudTrail を取り込み (CDR)、
"漏れた鍵での不審な API 呼び出し"・"権限昇格"・
"公開設定への変更" をクラウド側で検知し、CSPM が「そもそも鍵を平文で
置かない / 露出させない」姿勢を継続評価する。ホスト内 Falco と
クラウド面 CDR/CSPM の二層が本番の守り方。

# クリア条件

`Find AWS Credentials` が発火する → 自動で CLEARED。
