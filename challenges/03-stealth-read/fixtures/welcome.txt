# シナリオ

Mission 02 で正面切って `/etc/shadow` を読んだら盛大に検知された。
CTF Company の SOC はもう alert を見ている可能性が高い。
**だが諦めない**。同じ情報を、Falco に気づかれない方法で取り直す
ことができれば、SOC は「単発の false positive」と判断するはず。

# ゴール

`/etc/shadow` の末尾に**この Mission 用の flag**が書かれている。
flag を取り出し、scoreboard に提出せよ。**ただし**直前 10 秒間に
"Read sensitive file untrusted" を発火させてはならない。

# 背景

Falco のルールは多くの場合 **fd.name (= open に渡された path)** で
判定する。同じファイル本体に **異なる path** で到達できれば、検知
ロジックからは別物に見える。

# 試すこと

下の HINT を順に開封しながら、`cat /etc/shadow` ではない方法で
中身を取り出すアプローチを探そう。

# 提出方法

  source /opt/ctf/submit.sh
  submit 03-stealth-read 'FALCO{...}'

レスポンス:
  {"correct":true,"evaded":true,"solved":true,"user":"alice"}    ← 成功
  {"correct":true,"evaded":false,"reason":"forbidden rule..."}    ← 発火していた
  {"correct":false,"reason":"flag mismatch"}                       ← flag 違い

`evaded:false` が出たら **10 秒待ってから** もう一度 `submit`。

# 環境にあるもの

  /opt/ctf/missions/03-stealth-read/fixtures/welcome.txt   ← このファイル
  /opt/ctf/submit.sh     ← `source` して使う

────────────────────────────────────────────────────────────────────
HINT 1 (気付き): ルールは「本体」ではなく「パス」を見ている
────────────────────────────────────────────────────────────────────

同じファイル本体に、違う名前 (パス) でたどり着く方法は Linux に
いくつもある。Falco のルールが見ているのが「ファイル本体」では
なく「open に渡したパス文字列」だとしたら — どこを突けば抜ける?

────────────────────────────────────────────────────────────────────
HINT 2 (概要): /etc で始まらない path を探す
────────────────────────────────────────────────────────────────────

ルールは「パスが /etc で始まる」かどうかで判定している。同じ
inode (中身) に **/etc 以外のパス** で到達できればすり抜けられる。
`man proc` を読むか、`/proc/self/` の中を覗いてみよう。

────────────────────────────────────────────────────────────────────
HINT 3 (解答): /proc/self/root 経由で読む
────────────────────────────────────────────────────────────────────

  cat /proc/self/root/etc/shadow | grep FALCO

`/proc/<pid>/root` はそのプロセスの mount namespace の root を指す
symlink。fd.name = "/proc/self/root/etc/shadow" は /etc 始まりでない
→ 発火しない。`cat /proc/$$/root/etc/shadow` などでも可。
